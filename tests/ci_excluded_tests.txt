# nf-test files deliberately NOT run by .github/workflows/nf-test.yml.
#
# CI runs an explicit allowlist of test files, so a new test file is silent by
# default: it is committed, it is never executed, and nothing says so. The
# 2026-10-26 real-time audit found 41 of 101 test files in that state
# (docs/performance/realtime_many_barcodes_audit_2026-10-26.md, F13), including
# two pure-function suites excluded only because their filenames begin with
# "realtime". tests/lib/tests_are_wired.py now fails when a test file is
# neither referenced in the workflow nor listed here with a reason.
#
# Format: <path> <reason-code> optional free text.
# Reason codes:
#   watchpath   exercises Channel.watchPath; leaks the commons-io
#               FileAlterationMonitor thread on the GitHub ubuntu runner and
#               hangs the job (docs/upstream-issues/26-watchpath-cleanup-hang.md).
#               The realtime + validation e2e runs in the macOS realtime-e2e job.
#   nf-core     an upstream nf-core module/subworkflow test, maintained upstream
#               and needing the real tool or container.
#   unverified  no reason to exclude it has been established; it has simply
#               never been enabled. Enable after one local green run.
